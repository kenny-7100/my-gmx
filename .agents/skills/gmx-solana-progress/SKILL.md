# Solana 迁移实际进度

遵守根目录 [AGENTS.md](../../../AGENTS.md)，先阅读[进度评估方法](../../../docs/solana-progress.md)。评估是只读分析，允许保存忽略目录内的本地证据记录，不自动开始开发或修改线上状态。

1. 使用 [gmx-linear-requirements](../gmx-linear-requirements/SKILL.md) 刷新并阅读 FESOL 全量需求正文和状态，核对项目、标签、父子项、拆分、重复、取消及后续替代方案。追踪其他团队中相关的 API、设计、基础设施需求，并记录查询覆盖。影响范围、完成判断或阻塞的需求补读实时评论与双向关系。
2. 按[参考仓库入口](../../../docs/solana-reference-repositories.md)建立仓库、分支和 PR 清单。在线分页枚举相关仓库的分支和 PR，用需求链接、编号、旧编号、标题、提交和改动路径交叉识别迁移工作；检查上游目标分支、个人镜像、开放 PR、相关开发分支及本地未交付实现的真实代码。记录 SHA、diff、调用路径、审查/检查及部署证据，不以分支名或 Linear Done 替代核验。
3. 将范围归并成不重复的工作包，建立需求—代码—验收证据台账。父子项、多个分支和重做的旧架构代码不能重复计量；区分已写代码、PR 待合并、上游已合并及真实集成验收，按剩余实际工作估算完成比例，不给状态套固定百分比。
4. 计算两个工作量加权进度：现有 Linear 有效迁移范围，以及按已确认完整迁移标准所需的全部工作。后者补入有依据的未建单缺口；未确认的产品范围只列为敏感性情景，不擅自计入确定分母。权重、完成区间及其依据见主题文档。
5. 输出两个约数、估计区间、置信度与各自分母，附简短中文现状和含义一致的英文现状；指出主要剩余工作、阻碍、已开发但未交付能力及关键证据缺口。证据不足时不给无依据的数字，不把总体工作量进度解释为发布日期或上线就绪度。
6. 将本轮范围、证据、估算及相对上轮的变化保存在 `.local/solana-progress/`；区分实际推进、范围变化和估计修正。仅完整成功的评估更新最新指针；不覆盖历史或把不完整记录标为最新结果。

复用现有 Linear 工具和[GitHub 核验原则](../../../docs/solana-next-task.md)，不另建同步器，不记录凭据。通过 CLI/API 在线读取，不自动 fetch/pull、切分支、运行测试、构建、部署、打开浏览器或发送交易。缺少权限/资源时暂停依赖该条件的核验并说明缺口，仍可完成独立分析；不以旧快照、模拟数据或未经证实的替代服务冒充本轮证据。
