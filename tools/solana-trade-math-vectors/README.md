# Solana trade math reference generator

Status: **compiled and accepted with Rust 1.90.0** on 2026-10-28. Cargo.lock and vectors.json retain the locked dependency graph and 71 model-generated reference cases. The original 43 case inputs/outputs are unchanged. Two runs were byte-identical; verify.mjs independently checked all results, source/input/lock provenance, 27 malformed-input/setup failures and model errors distinct from zero. This tool is not a production dependency or a replacement for the shared GMX SDK.

The binary calls the real `gmsol-model` at the exact v0.10.0 commit. It accepts `inputs.json` and writes JSON to stdout only after all cases have been evaluated. The initial input set covers:

- `FeeParams::fee`: a supplied combined discount factor, fee balance direction, zero, full discount and rounding. It does not authenticate or compute GT rank/referral composition.
- `PerpMarketExt::cap_positive_position_price_impact`: configured positive cap and available impact pool, negative/zero passthrough. It does not calculate raw impact, distribute the pool, execute an order or calculate acceptable prices.
- `PositionExt::pnl_value`: long/short, both collateral types, side aggregate OI across both collaterals, profitable zero/finite/unreached caps, losses and partial-close rounding. The tool seeds explicit read-only mathematical state through model test builders; it does not validate or execute that position.
- `PositionExt::check_liquidatable`: 28 deposit/increase-initialized positions and 84 probes, each at three adjacent raw index price units around an analytically derived boundary. Covers long/short and both collateral types, market minimum collateral, leverage minima and their tie, nonpositive collateral, ordinary versus liquidation factors, explicit protocol `None` fallback, price spread, opening/closing fees and exclusion of liquidation fees from the predicate. Both liquidation and ordinary margin-check reasons are retained. No `PositionStatus.liquidation_price` is used.

Amounts, USD20 values and factors are canonical integer strings. Prices are USD20 per smallest token unit. Each token's decimals are explicit. Fee output keeps the amount's input unit. Shared USD30 outputs append ten decimal places exactly, without i128 overflow. Model errors and `None` are distinct from real zero. Malformed inputs or setup failures abort the run; no partial reference set is accepted.

For the original positive-impact/PnL subset, only the fields read by each function are populated; unused fixed-tag `TestMarketConfig` defaults do not enter those read-only calculations. The liquidation subset executes the model's deposit and increase actions with explicit prices, liquidity amounts, collateral, size, minima and fee factors. Swap/position impact and swap fees are explicitly zero. Other action configuration (reserve/OI limits, PnL limits, borrowing/funding parameters and fixed-point adjustments) uses the exact tagged test model defaults; these are reproducible mathematical fixtures, not deployed market configuration. The model clock never advances, so accrued borrowing/funding is zero. These probes are loss-making and do not exercise the profitable PnL cap. Long-token prices follow index min only in the long-collateral scenarios; all three token price bounds are explicit in every probe. No RPC is executed.

The user authorized installing Rust 1.90.0 (Cargo/rustfmt), downloading dependencies and compiling/running this generator. Rust was installed with the minimal profile and without modifying shell startup files. This authorization does not cover other builds, deployment or transactions. Use the same explicit toolchain for compilation and execution. From the repository root:

```sh

cargo +1.90.0 fmt --manifest-path tools/solana-trade-math-vectors/Cargo.toml --check
cargo +1.90.0 run --locked --offline --manifest-path tools/solana-trade-math-vectors/Cargo.toml -- tools/solana-trade-math-vectors/inputs.json > /tmp/solana-trade-math-vectors.first.json
cargo +1.90.0 run --locked --offline --manifest-path tools/solana-trade-math-vectors/Cargo.toml -- tools/solana-trade-math-vectors/inputs.json > /tmp/solana-trade-math-vectors.second.json
node tools/solana-trade-math-vectors/verify.mjs /tmp/solana-trade-math-vectors.first.json /tmp/solana-trade-math-vectors.second.json
```

The locked dependencies are already downloaded locally. On another machine, download the same graph with `cargo +1.90.0 fetch --locked --manifest-path tools/solana-trade-math-vectors/Cargo.toml` before the offline commands; do not regenerate the accepted lockfile for routine runs. The verifier requires Node 22 and the built debug binary. It checks the independent arithmetic with BigInt only as an acceptance oracle; Rust model output remains the reference source. It never writes reference values. Publish a new vectors.json only after both runs and the verifier succeed; never redirect over an accepted file before successful exit.

The long uncapped inputs use a larger long pool so the cap actually remains above side PnL even with the price spread. All 71 accepted reference cases return ok. Separate adversarial runs check a real model conversion error and a liquidation-probe arithmetic error; errors never become a false liquidation result or zero. FeeParams::fee None is not reachable with canonical u128 inputs and factors constrained to [0, 10^20], so the defensive unavailable branch is not claimed as exercised. A liquidation factor must be present as a canonical string or explicit null; omission is rejected. Null exercises the tagged protocol's fallback, not a frontend fallback for a missing API field. SDK/API consumption and the remaining operations are subsequent work.

Full coverage and handoff: [trade math reference](../../docs/solana-trade-math-reference.md). Nonzero price impact, elapsed borrowing/funding, profitable liquidation states, minimum-position/decrease limits, general liquidation-price solving, acceptable-price boundaries, program discounts and rent/keeper transfers remain outside the accepted subset. Three-point boundaries are derived only for these fixed affine scenarios; they do not establish general monotonicity or validate a general-purpose binary search.
