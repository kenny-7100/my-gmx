# Agent 任务启动卡

更新日期：2026-11-12。本卡是日常执行入口，先按当前工作选择路径；分支/交付细节按需查[日常流程](linear-development-workflow.md)，不逐项执行所有入口。

先确认当前目标、实际工作区和需要的结果；有 issue 先读对应记录。已有登记用个人基础最新版 `agent-workflow.mjs status --project-dir PATH --issue FESOL-123` 恢复权威目录、阻碍和下一步；未登记的只读查询可直接定位记录，不必注册或建分支。已有开发/PR 现场接入方法仅在需要时查[register/rebind](linear-development-workflow.md#接入已有分支或-pr)。

| 当前工作 | 最短路径 |
| --- | --- |
| 纯文档维护 | 搜索相关主题、修改原入口，检查本次链接与 diff；不刷新无关 Linear/子仓库，不因本地提交运行工具或业务全量回归 |
| 独立工具维护 | 读取相关实现与调用方 → 修改 → 单项验证；跨工具共享改动或整体验收才全量回归 |
| 单条 issue 查询/调研 | 既有 issue 记录 → 按需实时查询 → 核实相关证据 → 简记结论；不启动开发交付流程 |
| 新需求或继续开发 | 恢复现场 → 核验当前需求及关键依赖 → 读取适用编码规范 → 实现与针对性验证；新建任务直接 start，内部已同步个人基础 |
| 跨仓库联调 | 在开发路径上增加本次涉及的契约、目标版本及服务归属核验，再选择所需环境入口 |
| 最终 PR 交付 | 按[最短交付路径](linear-development-workflow.md#最短交付路径)集中整理一次，在最终目标完成相关验证；不预先反复创建交付目录 |

## 执行与复用

- **只加载当前需要的资料。** 根规则、适用 skill 和相关 issue/专题构成当前上下文；读过且未变的规则沿用。先用路径、标题或精确搜索定位段落，不沿每个索引递归全文阅读；本次不涉及的排障与验收入口保持按需。
- **一次观察供多个环节共用。** 同一连续工作阶段已成功核验的 Linear、PR、release 和子仓库版本，供启动、实现、自审及记录复用。新需求/跨会话继续实施、进入交付、收到相关变化或发现证据缺口时，按[更新时机](linear-development-workflow.md#需求与上游的更新时机)刷新受影响来源；多个流程命中同一节点只查一次。issue 的 updatedAt 不代表评论、关系、PR 或部署均未变，不以固定缓存时长替代判断。
- **按影响选择验证。** 已知 suite 直接运行；范围不明才发现，复杂跨侧依赖才规划。命令已包含发现/预检时不另跑同一检查。独立工具改动选单项，跨工具共享改动或整体验收再全量；预计需要全量时可直接让它覆盖单项。适用上游检查仍须完成，不以零关联、未执行或局部 passed 代替。
- **通过后推进，不机械加码。** 结果复用须核对目标、源码/依赖、配置、工具链和所需环境仍适用；变化只重验受影响项。转入新的交付目标仍执行该目标必要检查；旧目录结果不能冒充新目标通过。无新改动、失败或未解风险时，相关检查通过即继续交付，不扩大范围来重复确认。
- **减少串行等待。** 独立搜索、文档读取和远端只读查询可批量并行并检查各自结果；有依赖的操作顺序执行，共享暂存区、回流、生成产物串行，大型检查按资源安排。多 Agent 仅在获授权且收益明显时按[分工约定](agent-collaboration.md)使用。
- **在自然节点保存知识。** 按[issue 入口](issues/README.md#工作过程中持续更新)合并更新经历与结论；note 只存当前执行状态及链接，专题只存通用方法。重要阻碍/易丢失决策及时保存，普通结果可在切片收尾合并记录、提交，不要求每条命令重复写四份。

## 按场景选择工具

| 需要什么 | 入口 |
| --- | --- |
| 前端/SDK 开发规范和执行前置 | [编码与自审](coding-and-self-review.md)，按当前任务阅读；类型检查和回归遵循上游要求 |
| 已知前端测试 | `yarn frontend:test-offline --project-dir PATH --suite src/PATH.spec.ts`，或目标原生测试命令 |
| SDK 源码回归 | [SDK 离线入口](sdk-offline-tests.md)，不必为纯计算测试先构建 |
| 不确定影响范围/确需多仓库测试 | [发现及全栈规划](agent-test-plan.md)，不能把发现成功当测试通过 |
| API 计算、数据库、路由和类型检查 | [API 入口](solana-api-local.md)，选择对应 profile，不使用共享数据库 |
| 页面验收 | [浏览器入口](solana-browser-smoke.md)，既有两项网络选择冒烟不能替代本需求页面验收 |
| 联调、日志和断点 | [工作区](solana-dev-workspace.md)，目标路径及 owned/borrowed 服务明确 |
| 真实服务/链上只读事实 | [服务表](gmx-live-services.md)、[RPC 工具](../tools/solana-rpc-proxy/README.md)、[钱包与 CLI](agent-wallet.md)，按任务核对当前资源 |
| 复杂验收或需要移交原始材料 | [严格交付证据](agent-delivery-evidence.md)、[证据包](agent-evidence.md)，按需使用 |

收尾时简短说明实际结果、未覆盖项和继续入口，检查 issue 记录与知识回流。失败先查[诊断](agent-failure-diagnosis.md)，只处理当前原因；构建/服务按根授权。用户仅要求 push 时直接遵循根规则。历史状态按原日期理解，其他专题从[索引](README.md)按需查阅。
