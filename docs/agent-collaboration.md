# Agent 分工、成果接收与整合

更新日期：2026-11-12。只有任务适合拆分且当前授权/环境允许时才使用多个 Agent；普通任务由单 Agent 直接完成。本页补充[日常开发流程](linear-development-workflow.md)，不增加固定会议、轮询或任务管理服务。

## 先判断拆分收益

获准使用多 Agent 时，只拆能独立推进、整合成本低于预期收益的工作。短任务直接完成；同文件或紧耦合逻辑由一个实现负责人处理，其他 Agent 定向查接口、追踪风险或审查，避免重复探索整条链路。

分派附上已确认的目标版本、关键证据/规则链接和未解问题，接收方按其范围补查；同一来源已有效核验时复用，不让各 Agent 重新全量读文档、查 Linear 或跑相同准备。协调 Agent 汇总 issue 知识与当前状态，各参与者返回新增发现和验证边界即可。独立只读工具可并行；共享 Git 写入、回流和生成资源串行。复用条件见[启动卡](agent-task-start.md#执行与复用)。

## 一个协调入口

同一任务指定一个协调 Agent，负责共享任务摘要、分工调整、成果接收、基础设施回流、最终交付分支和 PR。其他 Agent 返回各自成果，不同时替换共享 decisions/blockers/assignments。任务转交时先交接现状和未接收成果，再变更协调负责人；原负责人停止维护该任务的最终状态。

`note` 的 coordinator/assignments 是协作声明，写锁只串行化工具写入，不验证 Agent 身份、不锁住文件编辑，也不代替沟通。启动写任务前检查已有分工及 worktree；发生范围重叠时先交由协调 Agent 收敛，不靠抢锁或覆盖解决。

## 个人基础写入归属

同一时段的 `solana-integration` 写入、暂存、提交和回流由一个明确协调者负责；多个独立任务也先确认基础写入归属，不各自直接改公共文档。单 Agent 可直接维护，其他参与者将新增发现、来源与建议落点随成果返回，由协调者在自然节点合并保存。

基础 dirty 阻碍 sync/start/backflow 时，先检查改动来源和完整性；已审查的本任务沉淀可独立提交，其他任务或未确认草稿保留，继续可独立推进的工作。不为清空现场仓促提交、打包他人改动或自动 stash/reset。工具 write.lock 只覆盖其自身写操作，不能保护编辑器/原生 Git，不替代上述归属约定。

## 分工与工作区

| 工作 | 选择与约束 |
| --- | --- |
| 多个只读分析 | 可以共享 checkout；分别说明要回答的问题和依据，不切分支或修改他人现场。 |
| 可独立实现的模块 | 优先各自 worktree/临时分支，注明修改路径、输入输出契约和完成条件；超出范围先协调。 |
| 同文件或紧耦合调用链 | 一个实现负责人，其他 Agent 提供分析/审查；确需拆分时先确定接口再写。 |
| 共享配置、生成文件、个人基础回流 | 协调 Agent 串行整合；不让多个 Agent 同时操作同一暂存区或更新个人基础。 |
| 会写 SDK/路由/缓存的构建和服务 | 核对目录、端口、产物和 owned/borrowed 归属；共享资源有写冲突时串行，不为并行复制错误依赖或停止他人服务。 |

worktree 只隔离 Git 现场；端口、数据库、缓存、钱包和忽略的生成产物仍可能共享。页面/集成验收前核对目标代码目录、实际进程及访问地址对应，并检查必要的 API/RPC 目标。优先复用管理工具现有身份/归属输出，不额外填表；来源未知不算核实通过，不接管服务或清理他人资源。

日常提交只暂存本次负责的路径/hunk；用户仅要求 push 时仍按根规则执行。交付后只有登记的 delivery 是业务成果的权威入口；必要的临时协作 worktree 从当前 delivery HEAD 派生，结果由协调 Agent 接收，不恢复旧开发分支继续维护另一份实现，也不创建第二套 PR 交付线。

## 最小子任务约定

分派时写清：目标结果、允许修改的路径、已有接口/不可改变的条件、完成判断与返回方式。返回时写清：实际改动及 commit/diff 位置、验证命令/结果/目标版本、阻碍与未覆盖项、是否超出范围。简单任务几句话即可；不能只回复“完成、测试通过”。

有多个写任务需要追踪时，协调 Agent 用 note 保存少量当前分工，例如：

```json
{
  "coordinator": "main",
  "assignments": [
    {
      "id": "orders",
      "owner": "worker-orders",
      "worktree": "/path/to/orders",
      "paths": ["src/domain/orders/"],
      "goal": "Refresh affected orders",
      "contract": "Reuse the shared order model",
      "doneWhen": "Execution and cancellation paths reviewed",
      "state": "planned"
    }
  ]
}
```

paths 相对该工作区项目根，不得越出；worktree/contract/commit 可选，commit 使用完整 SHA。列表整体替换，只有协调 Agent 汇总修改；单 Agent 任务无需填写这些字段。工具只检查结构，不证明路径归属、成果已合入或验证已执行。

## 接收与最终验证

| 状态 | 协调 Agent 需要确认的事实 |
| --- | --- |
| produced | 子任务提供了可定位的成果和真实验证说明，尚未接收。 |
| accepted | 检查了 diff、范围、接口和前置，决定接收；还未保证进入权威分支。 |
| integrated | 成果已进入权威分支，记录实际目标提交；解决组合冲突并检查重复实现/遗漏。 |
| verified | 在整合结果上完成了该范围所需的组合验证，明确仍未覆盖什么。 |

planned 表示待执行。状态是 Agent 的当前声明，不是自动验收证据。A 和 B 各自通过不能推导 A+B 通过；协调 Agent 按最终 diff、相互依赖和上游要求选择必要验证。仍有效的局部结果可复用，接口组合、冲突解决和关键交互需在最终目标验证，不机械重跑所有检查。

结束时简短说明哪些成果已接收/整合/验证、哪些还受阻，以及下一入口；可复用经验回流个人基础。临时 worktree 不自动批量删除，先核实成果、未提交工作和资源归属。重复分派、覆盖、接收遗漏或重复验证时，修正分工与入口，不新增固定复盘负担。
