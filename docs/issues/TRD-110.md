## 二次深入核验：以 GMTrade 实际能力为边界

用户明确：在 GMX 现有 Swap 框架下尽可能完整支持 GMTrade；前端能独立完成的实现、技术验证与测试不算依赖阻塞。不再将 Market/Limit、多跳、Token-2022 等笼统列成待产品定范围的开工门槛。上一轮“暂无外部阻塞”只来自源码推断，证据不足以承诺完整等价；本轮补了真实 WASM 构造、生产 API 和链上只读核对。

### 实际执行的验证

1. **真实固定 WASM，而非仅看声明。** 直接实例化应用 vendor artifact，SHA-256 `e82184caacc60828f024743f88a0a92d97b9d3d55db6839e0d3fab8a9b46c840`。用配置里的 BONK-index WSOL/USDC 池 `BvC73...`，以及 WETH/USDC 池 `5KSsa...`，构造 MarketSwap/LimitSwap × 单跳/双跳 × WSOL/自动 wrap SOL 共 8 组，无签名序列化均成功；独立临时 payer 下单跳 841/873 字节、双跳 874/906 字节。另 min_output 更新 390 字节、关闭订单构造 739 字节。均未使用 LUT。本轮 payer 只用于离线构造、无资金、未保留私钥；金额、min_output、blockhash、订单地址是合成输入，不能作为可签名交易或链上执行证据。
2. **生产 API。** `https://solana.gmxapi.io/v1/markets/config` 与 `/values` 各返回 67 个市场，按 long!=short 得 9 类币对、10 个 mint。WSOL/USDC 有 18 池，WGMX/USDC 有 10 池；APE/USDC、WBTC/USDC、WETH/USDC 各 1 池，这 5 类均有启用池且本次 values 两侧 poolAmount>0。另 4 类各自唯一池被 disabled。正余额不代表任意金额可成交，未做报价/容量或 keeper 实测。
3. **链上读取。** 通过 release 配置的生产代理 `https://rpc.gmx.io/solana/fallback`，按协议 PDA seeds `market/store/marketToken`，对旧站 Go 市场列表、旧站 app 默认生产列表和当前 API 集合合并后的 99 个 token 读取 Market 账户，返回 context slots `473396075/473396076`。按当前 IDL 布局读取账户 owner、9176 字节长度、名称、enabled、long/short mint。链上 disabled 的确是 FARTCOIN/USDC、BONK/USDC、TRUMP/USDC、WIF/USDC 四池，不只是 API 推断；协议校验要求市场 enabled，共享路由也排除 disabled。
4. **真实 mint program。** 同 RPC 于 slot `473396441` 读取上述 10 个 mint，owner 全为标准 `Tokenkeg...`，没有 Token-2022。当前 PUMP 配置是 synthetic/index；不能把看到 PUMP Token-2022 metadata 就当普通 Swap 必须先做 Token-2022。旧站另有 PUMP/WPUMP 特殊转换判断，不能仅凭特殊判断认为已有可用池或擅自扩成此次硬前置。
5. **旧站当前路径。** `execOrder.ts` 按 GMW351 切换 execOrderOld/New；本轮补读 New 的 market/limit/update 实现，实际调用同类 create_orders/update_orders，Limit 修改 min_output。旧站 graph max_steps=5，先构图再模拟；其 `getSimulateResult.ts` 用 set_disable_vis(true) 绕开未装载的 swap virtual inventory，不能原样移植该近似作为金融正确性证明。必要 VI 数据可由现有 RPC/共享 API 能力接入，尚无已证实需新服务交付的阻塞。

本机复现材料位于忽略目录 `.local/trd110-review/`：probe.mjs/probe-results.json、read-markets.mjs/live-market-accounts.json/live-market-summary.json、read-mints.mjs/live-mint-summary.json、live-config/values.json。正式结论和版本/slot/范围保存在本文，不以本机文件作为唯一接续证据。最初离线 owner 填写无效地址、Node ESM 缺 module.require 时失败；修正 probe 输入和运行适配后才取得上述结果，未归因 SDK 缺陷。RPC 裸命令或 Python 客户端曾返回 403；Node 加标准应用 Origin/Referer 后账户查询成功，不将其写成生产 RPC 故障。`/v1/markets/info` 探索请求为 404，Solana provider 使用 config/values，不能当缺少 Swap 后端的证据。

### 真正的外部限制与开工结论

- **可以开工，普通市价/限价及多跳不再只靠声明推断。** 现有固定 SDK 能构造上述代表性样本，无需先等待 SDK 发布；validator、报价一致性、状态跟踪仍是前端自身任务。样本不证明任意路径都不需 LUT，也不证明全部订单 ABI 和四钱包签名已验收。
- **四个 disabled 币对是当前运行边界。** 若目标是承接 GMTrade 当前实际可执行能力，应同样禁用，不阻塞其他币对实施；若要求恢复这四个池的交易，则依赖协议/运营启用与必要流动性条件，前端不能自行解除。旧站列表出现不等于旧站此刻真能成交。
- **存在已证实的选池覆盖差异。** 旧站默认列表中 BOME、MELANIA、TON 三池链上 enabled，但当前 API 和主项目静态列表不服务它们；三者都是 WSOL/USDC，并未新增币种。只用当前共享数据会少三个候选池，不能声称与 GMTrade 完全相同的流动性覆盖/最优报价。若验收要求完整覆盖这些池，应协调其纳入现有统一市场数据和 API 订单 served filter（当前会过滤任何含未服务池的 swapPath）；不先在前端私建另一套后端。可先开发现有池范围，此差异不构成整单开工硬阻塞，但它是完全等价交付需要收口的外部数据范围问题。
- **尚未执行受控真实 Swap/keeper 验收。** 未签名广播；现有开平仓 keeper 成功不能扩大为 Swap 成功。报价真实数值对比、部署 ABI、签后模拟与真实执行属于后续验收，不把“未验证”直接写为外部资源缺失。

最终判断：当前可开始实施；不能再无条件说“完全承接 GMTrade 不涉及任何外部事项”。实际已发现的外部边界是禁用池及三池统一数据覆盖；两者都不阻塞先实现当前可用路径。

## Refining 建议与实施条件

1. **确定首发矩阵。** 哪些 mint/池/路径允许，是否包含 Limit、是否允许多跳、Token-2022 是否支持。TWAP 明确排除；Jupiter/其他聚合路线没有由正文直接授权，不默认引入新服务。
2. **先细化独立 wrap/unwrap。** 共用生产 Swap UI；明确 1:1、ATA 创建/rent、SOL Max 留费、WSOL 关闭与释放租金、空余额/重复点击/拒签/未知结果。与 TRD-92 可复用钱包签名、余额和转账构造原则，但无需等待其整单完成；也不依赖 TRD-210 embedded。
3. **普通 Swap 建立一条可核对的报价→执行样本。** 固定真实 token/market 输入，比较共享报价与 pinned SDK 模拟，确认单位、路径、费用、impact、滑点 min_output；再实现 action/builder/validator，避免 UI 数字看似合理但交易含义不同。
4. **补完整生命周期验收。** keeper 执行后的实际收币、订单关闭/取消与费用返还、确认后的资产刷新、四钱包与桌面/移动、切网/换钱包/刷新恢复。交易 landed 不等于换币 executed。

可开始 refining 以及独立 wrap/unwrap 实施准备；普通 Swap 尚不能宣称前置全部满足并可直接验收。没有发现已证实必须新建 gmx-api 接口的硬前置，但报价与交易 ABI 的一致性、keeper 执行和真实钱包/资金/开关/RPC 条件未在本轮验证。TRD-101 原计划把 Swap 放在交易打通之后，是否提前并行要结合原交易线推进；本轮未改计划、认领或创建 PR。
