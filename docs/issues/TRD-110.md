# TRD-110 — Solana Swap

2026-11-24，参与角色：只读现状与 refining 调研，未认领实现。[Linear](https://linear.app/gmx-io/issue/TRD-110)。

## 当前结论

已有协议能力、旧站真实实现、共享 UI 和部分 Solana 报价计算，但当前 GMX release 没有可用的 Solana Swap 完整链路。普通 Swap 与独立 SOL/WSOL 转换都仍需接线，不能只打开功能开关，也不能把交易主线下单前自动 wrap 当成本需求完成。

Linear 当前为 **Refining / High，无实施 assignee**；正文 Owner 为 Chloe。2026-11-24 22:19 从 Backlog 变为 Refining，无显式 blocks/blockedBy，只关联 TRD-101。唯一评论是 Kenny 于 10 月 16 日表示会补技术前置，不是实现或验收记录。GitHub 按 TRD-110 未找到 PR；不能推断无人有未关联/本地工作。

## 代码与跨项目核验

### GMX 当前 release

固定基线 `993474e4377b75f919e587bc4f30e6adc24cecd1`，本轮在线核实未变。实际检查 feature、TradeBox Header、availableTradeModes、交易 hook、wrap executor、共享 swap selectors/math、Solana provider 和 vendor declarations。

- `src/config/features.ts`：Solana swap/twap 均 false；`TradeBoxHeaderTabs` 按 networkId feature 显示 Swap。
- `src/domain/synthetics/trade/utils/availableTradeModes.ts`：Swap 禁用时没有可选模式；已有 wrap 的 Market-only 判断显式列 Arbitrum ETH/WETH 与 Avalanche AVAX/WAVAX，不能假设直接支持 SOL/WSOL。
- `src/components/TradeBox/hooks/useTradeboxTransactions.tsx`：独立 wrap 读取 signer 后调 `createWrapOrUnwrapTxn`；后者是 WETH ABI deposit/withdraw。普通订单仍为既有 EVM 路径。
- 共享 `selectTradeboxSwapAmounts` 和 `makeSelectFindSwapPath` 沿统一 marketsInfo/tokensData 计算，可优先复用。Solana provider 的 globals.chainId 保留 EVM id；涉及原生币识别、gas 路径成本、外部 swap 报价、手续费的消费者要核对 network 语义，不能全局改 chainId 掩盖差异。
- 当前 vendored SDK `0.11.0-beta.1` 的声明已含 MarketSwap/LimitSwap、create_orders、MarketGraph、swap_path、min_output 与 native 选项。BUILD.md 固定源码 `7fe4008292ffc09061f3a733ad9b5cd2e6235fa8`；不能拿最新 protocol main 直接替代应用实际 artifact。

### 交易主线 PR #3337

[#3337](https://github.com/gmx-io/gmx-interface/pull/3337) 仍 OPEN / REVIEW_REQUIRED，base release，head `be9ca46ecba8031467bc13a7a771e1368d7aeccd`；当前 CI 均 SUCCESS，不代表 Swap 验收。

其 `transactions/README.md` 明确拒绝 swap routes 与未审查 Token-2022 account setup；`buildTradeboxOrderAction` 仅直接 position increase/decrease，increase 要求 noSwap 并构造空 swapPath。独立 MarketSwap/LimitSwap 也未作为已支持动作交付。因此它可提供签名、RPC 模拟、pending 恢复、钱包网络隔离和余额失效经验，但“等它合并”不会自动补齐 TRD-110。

复用其 sender 需要补 Swap 的输出 mint、路径、escrow/账户、滑点/min_output、费用与指令审查，不能放宽验证器后直接发送。是否需要升级 WASM 要由固定版本实际构造结果决定；现有声明不足以证明所有 Swap 交易已可用，也不足以断言必须升级。

### 旧 Solana 前端与协议 SDK

旧站官方 main `0e863b8dae7e1d9bef2cf28efe168b16c0992d20` 本轮在线核实未变：

- `useTriggerCreateSwapMarketOrder.ts` / `useTriggerCreateSwapLimitOrder.ts` 均真实调用 invokeCreateSwapOrder，带输入/输出 mint、amount、swapPath、native wrap/unwrap 标记；Limit 另有 minOutputAmount 与 triggerRatioAdjusted。
- `TradeBoxNew` 的模拟与工具代码调用 MarketGraph.best_swap_path，可作报价到执行的参考，不直接照搬旧 web3.js/Anchor/wallet-adapter 链路。
- `useUnwrapNativeToken.ts` 关闭用户 WSOL ATA；wrap helper 采用 transfer+SyncNative。不能无条件搬旧实现中的错误处理、账户已存在或手续费假设。

协议本地 main `3e0a4115ad975e972601f5e7a24f60a7ba52439b` 含 MarketGraph JS binding、MarketSwap/LimitSwap builder、swap simulation。远端已到 `b353d552c26f6ebd8f307c0e4c8e9d57ea324f7c`；在线比较仅新增 GT exchange rent collector 的 #520，未修改此次读取的 graph/order builder 路径。本轮未更新 checkout，未将本地旧 SHA 冒充远端最新。

### API 并非没有 Swap 基础

gmx-api 当前 main `f067594d40724a6116531d16d352f09c070cde2e`；与本轮源码快照 `f1a271e102b554200945ed4b1a88064b216c2c08` 比较没有修改 gmsol orders 相关路径。

`domain/gmsol/orders/orderRecords.ts` 已有 MarketSwap/LimitSwap 映射、swapPath、原始 token 单位 minOutput 和 actionState，且过滤不在已服务市场内的路径；不能默认任意代币/池均支持。它将 Swap triggerPrice/acceptablePrice 输出为 0；共享 `sdk/utils/orders/utils.ts` 已处理 contractTriggerPrice=0，按 minOutput 与默认滑点还原比例，因此 **0 不是已经证实的后端缺陷**。若包含 Limit，需用真实订单核对该还原比例、协议限价含义与编辑/取消路径，不先要求 Divhead 改接口。

## Refining 建议与实施条件

1. **确定首发矩阵。** 哪些 mint/池/路径允许，是否包含 Limit、是否允许多跳、Token-2022 是否支持。TWAP 明确排除；Jupiter/其他聚合路线没有由正文直接授权，不默认引入新服务。
2. **先细化独立 wrap/unwrap。** 共用生产 Swap UI；明确 1:1、ATA 创建/rent、SOL Max 留费、WSOL 关闭与释放租金、空余额/重复点击/拒签/未知结果。与 TRD-92 可复用钱包签名、余额和转账构造原则，但无需等待其整单完成；也不依赖 TRD-210 embedded。
3. **普通 Swap 建立一条可核对的报价→执行样本。** 固定真实 token/market 输入，比较共享报价与 pinned SDK 模拟，确认单位、路径、费用、impact、滑点 min_output；再实现 action/builder/validator，避免 UI 数字看似合理但交易含义不同。
4. **补完整生命周期验收。** keeper 执行后的实际收币、订单关闭/取消与费用返还、确认后的资产刷新、四钱包与桌面/移动、切网/换钱包/刷新恢复。交易 landed 不等于换币 executed。

可开始 refining 以及独立 wrap/unwrap 实施准备；普通 Swap 尚不能宣称前置全部满足并可直接验收。没有发现已证实必须新建 gmx-api 接口的硬前置，但报价与交易 ABI 的一致性、keeper 执行和真实钱包/资金/开关/RPC 条件未在本轮验证。TRD-101 原计划把 Swap 放在交易打通之后，是否提前并行要结合原交易线推进；本轮未改计划、认领或创建 PR。
