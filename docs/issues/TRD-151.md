### 已核实的重要实现边界

1. **同一客服应用不等于同一会话隔离语义。** 两边用浏览器随机 user ID，而非钱包 ID。GMX 的网络切换通过带 networkId key 的 SWR/provider 树重挂载 AppRoutes，已有 shutdown/boot 能复用，但 boot 环境仍须按真实网络设置。后端历史 conversation/contact 属性是否符合“不混标签”，不能只凭 SDK 调用断言，需要真实后台验收。
2. **旧站的断开保留会话是历史有意行为。** 2026-09-08 Kenny 提交 `d22f0687`（#893）明确 preserve Intercom session when wallet disconnects。它不支持多网络切换，不能照搬来替换 GMX 生命周期，也不能将“保留会话”直接认定为旧站缺陷。
3. **旧站断开属性清空并未沿调用路径发送。** 虽然 userAttributes 有 Not connected/0，但 disconnected 时 schedule effect 直接 cancel 并 return，只 hide widget；因此不能声称它已清理服务端 contact 的旧钱包属性。重连会发送新属性，实际到达时间还受 scheduler 配额限制。此为静态路径结论，未实测后台保留情况。
4. **钱包身份不能从 wagmi 猜。** GMX 共享 Solana session 目前只暴露 address/disconnect/isRestoring；底层 `SolanaWalletSessionSync` 从 Privy Solana wallets 的 standardWallet.name 获取 walletId，但公开 session 未暴露 provider 名。实施应沿现有会话来源提供正确身份，不为聊天另造一个钱包连接源。
5. **EVM 上下文可能残留。** GMX `SupportChatEvmAttributes` 只在 EVM 挂载，设置 tracker context 的 effect 没有 unmount 清空；Solana 不写新上下文。恢复入口时若不补 Solana 写入/清理，可能把上一 EVM 钱包拼到客服报告。当前 release 已隐藏入口，不能把这个潜在问题描述成已观察到的用户事故。
6. **GMX 错误绑定比旧站弱。** tracker reportError 只存 info/time；getLatestError 在点击时合并当前钱包上下文，toast 本身不绑定错误。旧站 reportError 返回 error+wallet/time 快照，helperNotice 显式传给 toast，并对 errorId/同错误对象去重、递归排除用户拒绝；已有对应测试覆盖切钱包、去重和拒签。这里只读取测试，未运行。若为 Solana 补错误上下文，需保护事件发生时归属；修改 EVM 全部错误语义不自动包含在本次范围。
7. **Solana 状态通知尚未接入客服。** 读取 TRD-78 [#3316](https://github.com/gmx-io/gmx-interface/pull/3316) head `aa6660fcb0` 的 `useSolanaOrderNotifications.tsx` 与 `SolanaOrderStatusNotification.tsx`：failed 和 keeper 结果通过 toast.update/状态组件显示，未 reportError，也没有 Contact support。TRD-84 #3293 中部分校验 helperToast.error 也未传 tradingErrorInfo。删除 helperToast 的 Solana hide 不会让这些失败自动进入客服计数；需明确普通 error toast 恢复与交易状态失败覆盖的验收边界，不能静默扩大需求或宣称全部覆盖。

旧站 useTraderMetrics 通过 GraphQL 的 users.volume 和分页 volumeRecords 读总/30d 交易量，通过 usePayerSwapList/useTickers 估算钱包资产。Tier 为 Whale/Large/Active/Retail，按 volume30d/lifetime/portfolio 任一超过阈值匹配；GMX 另有 GMX Account 维度。旧站美元精度 10^20，GMX 为 10^30，不能直接复制数值计算。

旧站 scheduler 普通资产属性最短约 2 分钟更新；钱包/network/tier 变化优先，30 分钟最多 20 次，为优先变化预留 5 次，并支持去重、失败重试。GMX 当前属性在每个 account+boot ID 就绪后发送一次，后续相同 account/boot 不随行情持续刷新。两者行为不同；TRD-151 没要求新增 Solana 统计与 Tier，不应为恢复聊天依赖旧 GraphQL、ticker 或整套资产状态。
