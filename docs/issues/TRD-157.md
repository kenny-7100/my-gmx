## 测试协作经验（2026-11-26）

- **单测充分性的表述要保留边界。** 此前把“做好单元测试就行”说得过满，应修正为：固定字节 fixture 和定向单测可证明解码、归属筛选与旧 completion 防护；真实正常数据回放可补充兼容证据，均不能单独证明真实第三方样本、页面或钱包流程已验收。向合约开发者询问时，同时问“有没有可用样本”和“缺样本时是否接受这组测试作为当前验收依据”，不把后者写成既定结论。
- **公共地址不等于钱包控制权。** 获得 exchange、owner、receiver 及所需关联账户后，可以无需私钥执行 RPC 读取和真实函数回放；查到他人的 owner 地址不代表用户能连接该钱包或签名。页面验证任意地址还需已有只读查看能力或另行批准的隔离测试方式，不能直接要求用户连接查到的钱包。
- **第三方 receiver 的形成有前置状态。** 按本次核对的 SCSOL-27/协议规则，独立 payer 仅在新建 exchange 时设置 receiver；后续 request 不改变已存在 exchange 的 receiver。因此 payer≠owner 本身不保证出现第三方 receiver，需同时确认采用的新指令与 exchange 是否首次创建。零个现存样本不能推出该状态永远不会存在。
- **先找可达样本，再讨论测试缺口。** 优先从需求、评论、设计及 PR 找公开线索，再扫目标网络现存程序账户，并核对 vault confirmed、Store、season、SQD protocolValid 及 exchange/vault 配对。真实账户若被上游筛选掉，就不能覆盖页面目标分支。记录 slot、筛选和分页范围；分别核实合入、部署、启用、索引及页面可达，不相互代替。详细调查证据见本文件上方。
